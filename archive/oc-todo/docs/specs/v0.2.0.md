# oc-todo v0.2.0 — Tier 1 slice

Baseline: v0.1.2 (`501033c`). Delta: four features, contract change (item shape +
tool schema + RPC + tests). No new automated decisions — features add storage and
render only.

## Item shape

```ts
interface TodoItem {
  id: string
  content: string
  status: "pending" | "in_progress" | "completed" | "cancelled"
  priority: "high" | "medium" | "low"
  notes?: string[]            // NEW — omitted when empty
  createdAt: number
  updatedAt: number
}
```

`notes` is optional and omitted (never `[]`) when there are no notes. No other new
keys. RPC `todo.list` output row gains optional `notes`; `additionalProperties`
stays `false`.

## #4 Counts summary line

`format(state)` keeps one line per todo exactly as today. It appends, as the LAST
line, `"<o> open · <p> in progress · <d> done"` where `open` = `pending`,
`in progress` = `in_progress`, `done` = `completed`; `cancelled` is counted in none.
Separator is space-middot-space. Empty list stays exactly `"No todos."` (no counts
line). Notes rows (below) sit between the item line and the summary; the summary is
always the final line.

## #3 Notes

- `add` accepts `notes`; coercion: keep only `string` entries, trim each, drop
  empties; omitted/empty result → field omitted.
- `update` accepts `notes` and REPLACES the array (same coercion); a present empty
  array clears the field. Equality is array equality; identical notes are a no-op.
- `write` entries accept `notes` and carry through like other optional fields.
- `coerce` repairs a malformed stored `notes` (non-array, non-string entries) to a
  valid array or drops it — never throws.
- `format`: an item with notes appends `  - <note>` lines (two-space indent) under
  its item line.

## #2 Move / reorder

New action `move`, input `{ action, id, before?, after?, position? }`.

- `id` resolves via `findTodo`.
- Exactly one of `before` / `after` / `position`. None → summary
  `"move: give before, after, or position"`. More than one → summary
  `"move: give exactly one of before, after, or position"`; the call changes
  nothing (refused before any mutation). The tool schema's `oneOf` guard is
  scoped to `action: "move"` so a non-move call is never rejected for carrying
  extra selector keys.
- `before`/`after` resolve via `findTodo`; unknown/ambiguous → error summary naming
  it, state unchanged.
- `position` clamped to `[0, length]` after removal.
- No-op (already at target index) → `"nothing to change"`, `updatedAt` unchanged.
- Real move → bumps `updatedAt`, summary `Moved "<content>" to position <n>`.

## #1 Cross-session list

`todo.list` stays per-session. NEW RPC method `todo.open` (registered alongside
`todo.list`) returns
`{ todos: Array<{ sessionID, id, content, status, priority, updatedAt }> }` — every
non-completed, non-cancelled todo across ALL stored sessions, each tagged with its
`sessionID`. Enumerated via `ctx.storage.scan({ prefix: "todos/session/" })`
(paged by `next`), confirmed against `@opencode/plugin` types and the V2 source.

NEW tool action `"open"` on the `todo` tool: one line per item
`(<sessionID>) [<priority>] <content>`, plus the #4 summary line as the final line.

## Acceptance criteria

- Counts: `cancelled` excluded; empty list unchanged; per-item lines unchanged.
- Notes: round-trip, malformed repair, clear, no-op equality.
- Move: before/after/position, clamp, no-op, unknown target, missing selector.
- `todo.open`: aggregation across ≥2 sessions, completed/cancelled excluded.
- Existing 32 tests still pass; TUI render rules unbroken.
