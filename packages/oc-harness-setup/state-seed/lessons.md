# lessons (seed)

Starter lessons installed with the harness. Replace with findings from real sessions; each lesson names its mechanism, its canary, or `instructed`.

## Index

- verification: every claim needs a runnable check that can fail (mechanism).
- memory: one session file per session, fixed key order, never invented ids (mechanism).
- scope: one ticket, one artifact, one check per pass (instructed).
- research: load-bearing claims cite primary sources or stay UNVERIFIED (mechanism).
- cleanup: scratch lives in temp and is swept at pass close (canary: `git status`).
- growth: one extension at a time (instructed).

## Lessons

- Run the proving check on real inputs and cite command plus output; a check that cannot fail proves nothing (mechanism: verifier verdict, canary: red seed per gate).
- A verdict comes from a seat that did not write the work; a self-verdict is not a verdict (mechanism: fresh verifier per pass).
- Take the session id from the session-rename return; never invent one, never reuse another session's (mechanism: fixed key order `id`, `title`, `status`, `goal`, `next`, `artifacts`, `decisions`, `open`).
- Keep commands and skills 1:1; a command with no skill behind it is a doc pretending to be a tool (mechanism: doctor check).
- Say UNVERIFIED out loud rather than filling a gap with a recalled answer (instructed).
- Leave no trail: untracked test artifacts, logs, and probe files are deleted in the turn they stop being needed (canary: clean `git status --short` at pass close).
- Grow the harness by one extension at a time; a niche skill is rejected or generalized, and a new seat needs a new reach class, not a new craft (instructed).
